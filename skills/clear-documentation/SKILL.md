# Clear Documentation

Write documents that help the intended reader understand a concept, complete a task, or find a precise fact.

## Choose the document's job

Use a tutorial for guided learning, a how-to for completing a task, a reference for lookup, or an explanation for understanding a concept. If one artifact must serve several jobs, separate those sections and make the route between them clear. Keep the reader's immediate task easy to find.

## Write and verify

1. Identify the audience, starting knowledge, prerequisites, and useful end state. Read the relevant supplied sources and existing document conventions.
2. Lead with what the reader needs now. Put prerequisites and conditions before the steps they govern. Write sequences as numbered actions with expected results.
3. Name who does what. Use present tense for current behavior and commands for instructions. Keep one term for each concept and define unfamiliar vocabulary where it first matters.
4. Split dense sentences. Keep necessary articles and verbs. Make pronouns unambiguous and place words such as "only" beside the thing they qualify.
5. Use concrete examples, valid identifiers, and current paths. Distinguish an illustrative example from a command that was actually run. A claim about a UI needs an observed current interface or a stated limitation.
6. Check links, factual claims, and task steps against permitted evidence. Note unsupported or outdated details. Keep warnings immediately before the action they affect.
7. Remove filler, hype, repeated explanations, decorative formatting, and needless summaries. Keep depth when the topic requires it.

Deliver the document in the requested format. Where practical and authorized, test a procedure from its stated starting point and record the result. A reader should be able to identify the next action and recognize success without guessing. Document creation or editing follows the task's existing permissions and destination.
