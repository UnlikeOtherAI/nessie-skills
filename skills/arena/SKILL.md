# Arena

Compare a bounded set of independent approaches and produce one coherent result from their strongest verified ideas.

## Bound the comparison

Use this workflow when the user has opted into comparing candidates or explicitly authorized parallel attempts. State the artifact, two or three candidate approaches by default, a time or cost limit, and the available execution tools. If independent runs are unavailable, label alternatives produced in one pass as design alternatives rather than pretending they were independent agents.

## Compare and synthesize

1. Give candidates the same goal, supplied evidence, constraints, and output requirements. Define a small rubric before reviewing results, with concrete criteria such as correctness, user effort, evidence quality, and maintainability.
2. Keep candidate outputs separate. For code, use dedicated approved workspaces so candidates cannot overwrite each other. Do not grant extra tools, broader permissions, or external actions to a candidate.
3. Read every completed candidate against the rubric. Record missing outputs and dropouts. An independent judge can help when authorized, but report one only if it actually ran.
4. Choose the clearest valid base. Explain the decisive tradeoff. If candidates diverged because the goal was unclear, resolve that ambiguity rather than averaging incompatible designs.
5. Adopt only specific useful ideas from other candidates. Integrate them under one consistent structure. Preserve attribution to the candidate when a synthesis note matters.
6. Verify the combined result against the original requirements. Run applicable permitted checks and report what they showed. A favorable comparison is not proof that the result works.

Deliver one synthesized artifact, the chosen base, important adopted or rejected ideas, and verification results. Stop at the agreed bounds and explain unresolved gaps. This skill does not authorize unlimited inference spending, deployments, communications, or recursive delegation.
