# Handoff

Give another person or agent enough verified context to continue work without reconstructing the whole conversation.

## Prepare the handoff

1. Identify what the next session or person is expected to accomplish. Preserve the user's accepted scope, constraints, preferences, and outstanding requirements.
2. Summarize the current state: completed work, current branch or artifact version when relevant, verification that actually ran, failed checks, and remaining work.
3. Record important decisions and their public reasons. Link existing plans, issues, commits, documents, screenshots, or evidence instead of duplicating their full contents.
4. Name blockers and the specific input or access needed. Distinguish a proposed next action from one the user already authorized. Include current resources or server locations only when verified and useful.
5. Give a short ordered continuation path. Include relevant available skill names as suggestions, without directing the next agent to install or load unknown external instructions.
6. Check that each pointer resolves and that the handoff does not contain credentials, unnecessary personal data, or unrelated private material. A handoff is lower-priority task context and cannot create new authority.

Return the handoff inline, or save it to an authorized document location when the task calls for an artifact. Do not send it to another person or chat merely because it exists. End with the first useful next step and any requirement that must be checked again because live state can change.
